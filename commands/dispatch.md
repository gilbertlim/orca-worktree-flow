Orca 워크트리를 만들고 작업 에이전트를 실행한다.

인자: `$ARGUMENTS`

## 실행 위치

우산 레포의 워크트리 안에서 실행한다. `pwd`가 `~/orca/workspaces/<레포>/<이름>` 형식인지 확인한다. 메인 체크아웃이면 우산 워크트리를 먼저 만들도록 안내한다. 메인에서도 실행되지만 소속을 나타내는 접두가 붙지 않아 작업을 구분하기 어렵다.

생성된 이름에는 `<우산레포>.<우산워크트리>.`가 붙는다. 이후 명령에 사용할 수 있도록 접두를 포함한 이름을 사용자에게 전달한다.

## 대상 레포

첫 인자에 레포 이름이 있으면 사용한다. 없으면 사용자에게 묻기 전에 후보를 확인한다.

```
${CLAUDE_PLUGIN_ROOT}/bin/dispatch.sh --repos
```

현재 레포와 같은 Orca 프로젝트 그룹의 레포를 `이름<TAB>메인 체크아웃 경로`로 출력한다. 그룹 밖까지 보려면 `--repos --all`을 사용한다.

1. 우산 워크트리의 `CLAUDE.md`에서 레포별 담당 범위를 확인한다.
2. 판단하기 어려우면 후보 레포의 메인 체크아웃에서 `CLAUDE.md`와 `README.md`를 읽는다.
3. 작업 설명의 도메인 용어, 파일 이름, API 이름을 후보 레포에서 `grep`으로 확인한다.

후보가 하나로 좁혀지면 근거 한 줄과 함께 선택한다. 둘 이상 남거나 근거가 부족하면 후보별 근거를 제시하고 사용자에게 선택을 요청한다. 목록만 보여 주고 판단을 맡기지 않는다.

레포 이름은 경로가 아니라 Orca에 등록된 `displayName`이다.

## 워크트리 이름

`<동작>-<대상>` 형식의 케밥케이스로 2~4단어를 사용한다.

```
우산:  orca-worktree-flow/login-refactor
서브:  orca-worktree-flow-sub-repo/orca-worktree-flow.login-refactor.auth-api
탭:    auth-api
```

- 우산 이름은 기능 전체를 나타낸다. 예: `login-refactor`, `add-trade-column`.
- 서브 이름은 해당 레포의 작업을 나타낸다. 예: `auth-api`, `trade-schema`. 접두에 있는 기능 이름은 반복하지 않는다.
- 접두 `<우산레포>.<우산워크트리>.`는 스크립트가 붙이므로 인자에 넣지 않는다.
- 터미널 탭은 워크트리 안에 있으므로 제목에는 접두 없는 이름만 사용한다.
- 경로에 이미 있는 레포 이름은 워크트리 이름에 반복하지 않는다.
- 브랜치 이름은 Orca가 생성한다. Git 사용자명이 앞에 붙을 수 있다.

이름 인자가 없으면 작업 설명에서 정하고 사용자에게 알린 뒤 진행한다.

## 실행 순서

1. 레포와 이름을 정한다. 나머지 인자는 작업 설명으로 사용한다.
2. `${CLAUDE_PLUGIN_ROOT}/templates/prompt-template.md`를 기준으로 프롬프트 파일을 작성한다. `.orca-flow.json`의 `promptTemplate`이 있으면 우선 사용한다. 워크트리의 에이전트는 이 세션의 서브에이전트 정의나 프로젝트 루트의 상대 경로에 접근할 수 없으므로 역할을 명시하고 읽을 문서는 절대 경로로 적는다. 파일은 스크래치패드나 `/tmp`에 두어 프로젝트 커밋에 포함되지 않게 한다.
3. 프롬프트를 사용자에게 보여 주고 확인받는다. 워크트리 생성과 에이전트 실행은 되돌리기 번거로우므로 실행 전에 내용을 확인한다.
4. 다음 명령을 실행한다.

```
${CLAUDE_PLUGIN_ROOT}/bin/dispatch.sh <repo> <worktree-name> <prompt-file>
```

5. 출력된 경로와 브랜치를 사용자에게 전달한다.

레포가 여럿이면 레포별 작업에 맞는 이름으로 각각 실행한다. 디렉터리가 달라 서로의 파일을 수정하지 않는다. 같은 이름의 워크트리가 있으면 스크립트가 중단된다. 기존 작업은 `/orca:review`나 `/orca:handback`으로 이어간다.

`AGENT_CMD`, `BASE_BRANCH`, `NO_SETUP=1`로 한 번의 실행을 조정할 수 있다. 우산을 직접 지정하려면 `ORCA_OWNER=<repo>.<name>`을 사용한다.

한 우산 워크트리에서는 기능 하나만 다룬다. 이미 다른 기능을 진행 중이면 새 우산 워크트리에서 시작하도록 안내한다.
