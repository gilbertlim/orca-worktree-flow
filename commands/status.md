현재 있는 모든 워크트리의 상태를 확인한다.

인자: `$ARGUMENTS` (레포 이름 하나를 주면 그것만, `--all`이면 우산과 상관없이 전부)

우산 워크트리 안에서 부르면 **이 우산이 만든 것만** 찍는다. 서브 레포 하나를 우산 여럿이 겨눌 수 있어서, 남의 워크트리가 표에 섞이면 다음 단계를 남의 것에 대고 부르게 된다.

```
${CLAUDE_PLUGIN_ROOT}/bin/status.sh $ARGUMENTS
```

출력을 그대로 전하되, 사람이 다음에 무엇을 해야 하는지 한 줄로 짚는다.

| 무엇이 보이면 | 다음 단계 |
|---------------|-----------|
| 커밋이 있고 리뷰가 "안 함" | `/orca:review` |
| 리뷰가 "낡음" | 고친 뒤 재리뷰를 안 돌린 상태다. `/orca:review` |
| 카드에 "리뷰: blocking N건" | `/orca:handback` |
| 카드에 "리뷰 통과" | `/orca:land` |
| 터미널이 `막힘` | 에이전트가 사용자 입력을 기다린다. 그 탭을 열어 답한다 |
| 리뷰 칸이 `5차`이고 상한에 닿음 | 왕복을 더 쓸지 land할지 사람에게 묻는다 |
| 미커밋이 쌓여 있고 터미널이 없음 | 에이전트가 죽었다. 그 워크트리를 열어 본다 |
| 끝에 `▶ 전부 닫혔다` | **멈추고 사람에게 묻는다.** 아래를 본다 |

## 전부 닫혔으면 혼자 land하지 않는다

내가 낸 워크트리가 모두 커밋이 서고, 미커밋이 없고, 판정이 최신이고, blocking이 0이면 스크립트가 마지막에 그 줄을 찍는다.

```
▶ 내가 낸 워크트리 2개가 전부 닫혔다.
  진척을 기록하고 land할지 사람에게 묻는다.
```

그 줄이 뜨면 **폴링을 멈추고 사람에게 묻는다.** 각 워크트리가 무엇을 했는지 한 줄씩 보여 주고, land할지를 확인받는다. 혼자 land하지 않는 것은 머지 순서가 이 표에 안 보이기 때문이다 — 여러 레포가 함께 커밋돼야 하는 변경은 한쪽만 먼저 들어가면 계약이 깨진 중간 상태가 남는다.

일부만 닫혔으면(`▶ 3개 중 2개가 닫혔다`) 아직 묻지 않는다. 남은 것이 무엇을 기다리는지 한 줄로 짚고 계속 본다.

**우산 워크트리 자신도 묻는다.** 오케스트레이터가 앉은 자리라 서브 레포와 조건이 다르다 — 리뷰를 안 거치는 자리이므로 판정 파일은 안 보고, 미커밋이 없고 기준 브랜치보다 앞서 있으면 그 줄이 뜬다.

```
▶ 이 우산 워크트리에도 main 앞에 커밋 3개가 서 있다.
  land할지 사람에게 묻는다. 이 워크트리 안에서 부르면 지우지 않고 머지와 push만 한다.
```

이 줄이 있어야 우산 워크트리에서 직접 만든 변경도 사용자에게 land 여부를 확인할 수 있다.

판정을 추측하지 말고 카드 문구와 리뷰 칸에 표시된 내용만 전달한다.

표 아래에 기록 파일의 마지막 몇 줄이 따라 붙는다. 무엇을 언제 내보내고 몇 차에 닫았는지가 거기 쌓이므로, 세션을 이어받았으면 그 줄부터 읽는다.
