작업 중인 워크트리에서 리뷰어를 실행한다.

인자: `$ARGUMENTS`

## 실행 순서

1. 첫 인자는 레포, 둘째는 워크트리 이름이다. 나머지는 중점적으로 검토할 내용이다.
2. 중점 검토 사항이 있으면 프롬프트 파일로 작성한다. 없으면 기본 리뷰 지시와 `.orca-flow.json`의 `review.context`를 사용한다.
3. 다음 명령을 실행한다.

```
${CLAUDE_PLUGIN_ROOT}/bin/review.sh <repo> <worktree-name> [prompt-file]
```

4. 판정 파일 경로를 사용자에게 전달한다. 완료를 기다리지는 않는다. 리뷰는 워크트리 안에서 진행되고, 결과는 카드에 표시된다.

## 리뷰 실행 방식

리뷰어를 이 세션의 서브에이전트로 실행하면 여러 레포의 diff가 한 세션에 모여 컨텍스트 한도에 도달할 수 있다. 이 세션에서는 판정 파일만 읽는다.

- 미커밋 변경이 있으면 중단한다. 리뷰 중 diff가 바뀌면 판정과 커밋 내용이 달라질 수 있다. 그래도 실행하려면 `FORCE=1`을 지정한다.
- 기존 리뷰어가 있으면 재리뷰를 요청해 이전 지적과 현재 상태를 비교한다. 새 리뷰어를 실행하려면 `NEW=1`을 지정한다.
- 판정은 파일로 저장한다. TUI 출력만 남기면 스피너 화면 갱신으로 스크롤백에서 사라질 수 있다.
- 이전 판정은 `.round<N>.md`로 자동 보관한다. 2차부터는 이전 blocking의 해결 여부만 확인하고 근거 없는 지적을 추가하지 않도록 지시한다.
- 기본 상한은 5차다. 넘으면 남은 blocking을 출력하고 중단한다. 자동으로 `FORCE=1`을 사용하지 않는다. 실행 문제와 서술 정정을 구분해 제시하고 리뷰를 계속할지 land할지 사용자에게 묻는다. 상한은 `review.maxRounds`나 `MAX_ROUNDS=`로 변경한다.
