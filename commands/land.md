리뷰 지적을 해결한 워크트리를 기준 브랜치에 머지한다.

인자: `$ARGUMENTS`

## 실행 순서

1. 판정 파일에서 blocking이 해결됐는지 확인한다. 남아 있으면 `/orca:handback`을 먼저 실행한다.
2. 여러 레포의 계약이 연결된 변경이면 머지 순서를 사용자에게 확인한다. 한쪽만 반영하면 일시적으로 계약이 깨질 수 있다.
3. 다음 명령을 실행한다.

```
${CLAUDE_PLUGIN_ROOT}/bin/land.sh <repo> <worktree-name>
```

4. push 시 사용자 확인 프롬프트에서 최종 확인을 받는다.

## 환경변수

| 환경변수 | 동작 |
|----------|------|
| `KEEP=1` | 머지와 push 후 워크트리 유지 |
| `NO_PUSH=1` | 머지만 진행하고 push 생략. 워크트리 유지 |
| `FORCE=1` | 리뷰 파일이 없거나 메인 체크아웃에 미커밋 변경이 있어도 진행 |

## 중단과 정리 조건

- 리뷰 파일이 없으면 중단한다. 이미 머지된 워크트리를 정리할 때는 검사하지 않는다.
- 이미 머지된 워크트리에도 실행할 수 있다. push 실패 후 다시 실행하거나 `KEEP=1`로 남긴 워크트리를 정리할 때는 머지를 생략하고 push와 정리만 진행한다.
- 메인 체크아웃이 기준 브랜치가 아니거나 미커밋 변경이 있으면 중단한다. 여러 세션이 같은 체크아웃을 사용할 수 있기 때문이다.
- push 실패 시 복구할 수 있도록 워크트리를 유지한다.
- 현재 워크트리 안에서 실행하면 머지와 push만 진행한다. 셸의 작업 디렉터리가 삭제되지 않도록 워크트리는 남긴다.
- 리뷰 판정과 `.round<N>.md` 기록은 워크트리 삭제 후에도 보관한다. 나중에 판정 근거를 확인할 수 있다.
- land 결과를 기록 파일에 한 줄 추가한다. 워크트리와 카드가 삭제된 뒤에도 완료 이력을 확인할 수 있다.
